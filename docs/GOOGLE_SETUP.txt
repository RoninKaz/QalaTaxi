GOOGLE-ВХОД ДЛЯ ВЛАДЕЛЬЦА QALA TAXI

На главной странице только два кабинета: клиент и водитель.
Администратор — служебная часть, не роль публичной регистрации.
Отдельный адрес: http://127.0.0.1:8000/admin
При первом разрешённом входе Google аккаунт администратора создаётся автоматически.
Вход и регистрация администратора по телефону отключены.

НАСТРОЙКА (ОДИН РАЗ)
1. В Google Cloud Console создайте или выберите свой проект.
2. Настройте Google Auth Platform: название приложения, контакт владельца,
   аудиторию и тестовых пользователей, если проект в режиме тестирования.
3. Создайте OAuth client с типом Web application.
4. Добавьте Authorized redirect URI точно:
   http://127.0.0.1:8000/auth/google/callback
5. Скопируйте google_oauth.example.json в google_oauth.json в корне проекта (рядом с main.py).
6. В google_oauth.json заполните:
   client_id — Client ID из Google Cloud;
   client_secret — Client secret из Google Cloud;
   redirect_uri — тот же URI, который указан выше;
   admin_emails — список ваших Google-адресов, например ["yourname@gmail.com"].
   Укажите свой настоящий адрес вместо примера. Секрет не отправляйте в чат.
7. Запустите start.bat, откройте /admin и нажмите «Войти через Google».

Поддерживаются Gmail и Google Workspace с подтверждённым email.
Любой клиент/водитель не получает права администратора просто по факту входа в Google:
адрес должен быть добавлен владельцем в admin_emails.
Для нового администратора добавьте его Google-адрес в этот список.
Настройки перечитываются при обращениях; изменение списка доступа действует сразу.
Если используете другой порт, измените redirect_uri и запись в Google Cloud.
Открывайте приложение по 127.0.0.1, как в redirect_uri, а не по localhost,
иначе cookie начала входа не совпадёт с адресом возврата.

ЧТО УЖЕ РЕАЛИЗОВАНО
OAuth Authorization Code, PKCE S256, одноразовый state с привязкой к сессии
и сроком 10 минут, обмен кода сервером, получение профиля через HTTPS API Google,
проверка подтверждения email и списка доступа, идентификатор Google sub,
локальная сессия HttpOnly/SameSite и защита административных действий.
Пароль Google не вводится в Qala Taxi и не сохраняется приложением.
Токены Google используются только во время входа и не записываются в базу.

БЕЗ НАСТРОЕК
Клиент и водитель работают как раньше. Кнопка Google в служебном входе
неактивна с пояснением. Ненастоящего входа и обхода проверки нет.
Проверки Google выполнены тестами с подменёнными сетевыми ответами;
реальный вход нельзя проверить без OAuth-клиента владельца.

Документация Google:
https://developers.google.com/identity/openid-connect/openid-connect
Не включайте google_oauth.json или taxi.db в архивы с исходным кодом.

GOOGLE ДЛЯ КЛИЕНТОВ И ВОДИТЕЛЕЙ
На страницах входа и регистрации есть «Продолжить с Google».
Используется тот же OAuth-клиент и callback /auth/google/callback.
Клиент автоматически получает свой кабинет. Водитель сначала заполняет
телефон и автомобиль, затем сразу начинает работу.
Повторный Google-вход открывает существующий аккаунт по Google sub.
Один Google-аккаунт может иметь отдельные кабинеты клиента и водителя.
Админские права не выдаются клиентам/водителям; список admin_emails
относится только к служебному входу.
Google-вход и регистрация по телефону — отдельные аккаунты; автоматического
объединения по имени или телефону нет. Уже зарегистрированному по телефону
водителю следует использовать прежний способ входа.
В режиме Testing доступ Google может зависеть от настроек аудитории
проекта. Клиент и секрет сохраняются только в локальном google_oauth.json.
Настоящие входы клиентов/водителей ещё не проверены пользователем;
автотесты проверяют протокол с тестовыми ответами Google.
